# 자연어 → 3D 포즈 수치 데이터 맵

이 문서는 `skinned-v3` Bony 리그를 자연어 처리 모델에 전달하는 **모델 컨텍스트 계약**이다. 입력 자연어를 즉시 이미지 프롬프트로 보내는 용도가 아니다. 모델은 이 계약에 따라 `clicktoon.pose-intent/v1` JSON을 만들고, 앱의 [`poseIntentToState`](../lib/pose/natural-language-map.ts)가 실제 에디터·생성 API가 저장하는 `PoseState` 라디안 값으로 변환한다.

## 1. 변환 파이프라인

```text
사용자 자연어
  → 의도 추출 (인물 수, 역할, 동작, 방향, 관계, 접촉 의도)
  → PoseIntentDraft: 도(degree) 단위 JSON
  → 스키마/관절 범위/인물 수 검증
  → poseIntentToState: 라디안 PoseState
  → 기존 3D 편집기 미리보기 및 사용자의 보정
  → 기존 생성 파이프라인의 포즈 이미지
```

자연어 모델은 캐릭터 ID를 새로 만들거나 교환하면 안 된다. 애플리케이션이 보유한 캐릭터 ID를 피규어에 배정하며, 모델은 `role`과 포즈만 제안한다. 출력이 불명확하거나 충돌하면 포즈를 적용하지 말고 질문하거나 가장 가까운 프리셋을 제안한다.

## 2. 좌표계와 단위

| 값 | 규약 |
| --- | --- |
| 관절 회전 | AI 출력은 **도**, 저장되는 `PoseState.bones`는 **라디안**. 모두 기본(T 포즈) 관절 방향에서의 로컬 델타다. |
| 월드 X | `+X`는 화면 오른쪽. |
| 월드 Y | `+Y`는 위, `y=0`은 서 있는 인물의 바닥. 앉기·무릎 꿇기는 보통 음수 y가 필요하다. |
| 월드 Z | `+Z`는 카메라 쪽. |
| yaw | `0°`은 카메라(+Z)를 봄, `+90°`는 화면 오른쪽(+X), `-90°`는 화면 왼쪽(-X)을 봄. |
| 인물 수 | 1~3명. 2인 상호작용은 각 인물의 관절 외에 `position`과 `yawDegrees`가 필수다. |

좌우 관절 이름의 `l`/`r`은 리그의 왼쪽/오른쪽이다. 이 리그는 일부 축에서 사람 몸의 좌우 미러링과 같은 부호를 쓰지 않는다. 아래의 의미 단위와 기존 프리셋을 우선 사용하고 임의의 미러링 수식을 만들지 않는다.

## 3. AI 출력 스키마

다음 형식만 출력하게 한다. JSON 밖 설명은 별도 필드나 대화 응답으로 분리한다.

```json
{
  "schema": "clicktoon.pose-intent/v1",
  "figures": [
    {
      "id": "f1",
      "role": "speaker",
      "joints": {
        "shoulder_l": [0, -26, -58],
        "elbow_l": [59, -37, 0],
        "head": [10, 0, 0]
      },
      "placement": {
        "position": [-0.52, 0, 0],
        "yawDegrees": 68,
        "scale": 1
      }
    },
    {
      "id": "f2",
      "role": "listener",
      "joints": {
        "shoulder_r": [0, -8, -35],
        "head": [-8, 0, 0]
      },
      "placement": {
        "position": [0.52, 0, 0],
        "yawDegrees": -68,
        "scale": 1
      }
    }
  ],
  "interaction": {
    "relation": "facing",
    "description": "speaker gestures toward listener"
  }
}
```

`joints`에 없는 관절은 기본(T 포즈) 회전을 유지한다. `scale`은 생략하면 1이다. 애플리케이션은 모델 출력의 최대 관절 범위(몸통/사지/손가락)를 잘라내지만, 모델도 표의 범위를 넘지 않는 값을 출력해야 한다.

## 4. 신체 부위별 수치 맵

모든 관절 ID와 안전 범위는 [`POSE_LANGUAGE_DATA_MAP`](../lib/pose/natural-language-map.ts)에 기계가 읽을 수 있게 정의돼 있다. 아래 표는 자연어 해석에 필요한 축 의미만 요약한다.

| 부위 / 관절 | `[x, y, z]`의 의미 | 안전 범위 |
| --- | --- | --- |
| `root` | 앞뒤 기울기, 화면 오른쪽 회전, 화면 오른쪽 기울기 | x±30°, y±60°, z±30° |
| `spine` | 앞으로 숙임, 화면 오른쪽 비틀기, 화면 왼쪽 기울기 | 각 ±30° |
| `chest` | 화면 오른쪽 비틀기, 화면 오른쪽 기울기, 뒤로 젖힘 | 각 ±25° |
| `neck`, `head` | 화면 오른쪽 회전, 화면 오른쪽 기울기, 고개 들기 | x±35°, y±45°, z±30° |
| `shoulder_l/r` | 로컬 X, 뒤쪽 이동, **+위 / -아래** | 각 ±120° |
| `elbow_l/r` | 팔을 내린 상태의 앞으로 굽힘, T 포즈 상태의 뒤쪽 굽힘, 바깥쪽 비틀기 | 각 ±120° |
| `wrist_l/r` | 로컬 X/Y/Z | 각 ±120° |
| `hip_l/r` | +바깥 벌리기, 로컬 Y, +다리 앞으로 | 각 ±120° |
| `knee_l/r` | 로컬 X/Y, **-값이 무릎 굽힘** | 각 ±120° |
| `ankle_l/r` | 로컬 X/Y, +발끝 들기 | 각 ±120° |
| 엄지/검지/중지 1~3 | 각 손가락 관절의 로컬 X/Y/Z | 각 ±100° |

### 모델이 사용할 의미 단위

다음은 관절 벡터를 직접 추론하는 대신 우선 적용할 수 있는 해석 규칙이다.

- **팔 내리기:** `shoulder_* = [0, 0, -78]` 부근. 기본 T 포즈의 팔은 옆으로 수평이다.
- **팔 들기:** `shoulder_*.z`를 양수로, 팔 내리기는 음수로 한다.
- **팔을 앞으로 뻗기:** `shoulder_*.y`에 음수 값을 주고, 팔꿈치 굽힘은 어깨 높이에 따라 `x`와 `y`가 함께 달라진다. 안정적인 값은 기존 `arm(side, up, fwd, bend)` 패턴을 참조한다. [프리셋](../components/pose-editor/presets.ts)
- **다리 앞으로/무릎 굽힘:** `hip_*.z` 양수는 다리 앞으로, `knee_*.z` 음수는 무릎을 굽힌다.
- **앞으로 숙이기:** `spine.x`와 `chest.z`의 조합을 사용한다. 상체가 과도하게 꺾이지 않도록 각각의 제한을 지킨다.
- **시선:** `neck`과 `head`를 같은 방향으로 작은 값부터 적용한다. 머리만 크게 돌리지 않는다.
- **손가락:** 손 모양이 필요한 요청에서만 설정한다. 현재 손가락 관절에는 손바닥·물체 접촉을 보장하는 IK가 없다.

## 5. 인물 배치와 상호작용 맵

### AI에 전달되는 계산 규칙

패널의 **AI 컨텍스트 복사**에는 [`calculation-guide.ts`](../lib/pose/calculation-guide.ts)의 규칙·수치 예제·실패 사례·출력 전 점검 항목이 `calculationGuide`로 포함된다. 이전에 복사한 프롬프트는 자동 갱신되지 않으므로 새로 복사한다. 기존 에디터와 변환 포맷은 그대로 사용한다.

팔은 한쪽씩 의미 파라미터 `up`(수평 기준 높이), `fwd`(앞으로 보내기), `bend`(팔꿈치 굽힘)를 정하고 다음 공식으로 변환한다. 이는 기존 프리셋의 후보 생성 공식이며 접촉 위치를 푸는 IK는 아니다.

```text
t = up * PI / 180
shoulder = [0, -fwd, up]
elbow = [-sin(t) * bend, -cos(t) * bend, 0]
```

삼각함수 입력만 라디안이다. 결과 관절값은 도 단위이며 최종 JSON에는 계산식이나 `up/fwd/bend` 필드 대신 계산된 `joints`를 넣는다. 좌우 팔에 동일 의미를 적용할 때 임의로 부호를 반전하지 않는다.

| up / fwd / bend | shoulder | elbow (도, 소수 셋째 자리) |
| --- | --- | --- |
| -78 / 0 / 10 | [0, 0, -78] | [9.781, -2.079, 0] |
| 0 / 0 / 65 | [0, 0, 0] | [0, -65, 0] |
| -18 / 0 / 65 | [0, 0, -18] | [20.086, -61.819, 0] |
| -58 / 26 / 70 | [0, -26, -58] | [59.363, -37.094, 0] |

`shoulder=[0,0,-18]`, `elbow=[65,0,0]`을 “머리에 손 얹기”의 정답으로 사용하면 안 된다. 어깨가 거의 수평이고 앞으로 보내는 값이 없으며 팔꿈치 축도 공식과 다르다. 위 표에서 팔꿈치만 교체해도 머리 접촉까지 보장되지는 않는다.

정수리와 턱처럼 양손 목표가 다르면 각 팔을 독립적으로 계산한다. `contacts`에는 손목과 상대 `head`를 연결할 수 있지만, 현재 `head`는 관절 기준점일 뿐 정수리나 턱의 표면 좌표가 아니다. 실제 접촉은 월드 좌표와 별도 표면 기준점 측정이 있어야 검증할 수 있다. `description`과 `maxDistance`는 자동 보정 명령이 아니다.

인물 배치에서는 `yaw=atan2(target.x-self.x, target.z-self.z)*180/PI`로 상대를 향하는 방향을 구할 수 있다. 같은 방향으로 뒤에 서려면 앞 인물의 정면 벡터 `[sin(yaw),0,cos(yaw)]` 반대쪽에 배치한다. 서 있는 인물의 Y는 기본 0이며, 손을 닿게 하려고 `position.y`를 올리면 몸 전체가 공중으로 이동한다. 화면 방향 설명은 기본 카메라 기준이다.

2인 관계는 관절값만으로 판단할 수 없다. 아래 필드를 항상 같이 만든다.

| 관계 | 배치·방향의 출발값 | 접촉 의도 |
| --- | --- | --- |
| 마주보기/대화 | 왼쪽 `x≈-0.52`, `yaw≈+68°`; 오른쪽 `x≈+0.52`, `yaw≈-68°` | 선택적 손짓, `relation: facing` |
| 악수 | `x≈±0.42`, `yaw≈±82°` | 두 인물의 `wrist_r`끼리 `hold` |
| 하이파이브 | `x≈±0.46`, `yaw≈±78°` | 두 인물의 `wrist_r`끼리 `touch` |
| 포옹 | `x≈±0.28`, `yaw≈±84°` | 양쪽 팔/손목이 상대 상체 근처, `relation: embrace` |
| 어깨동무 | `x≈±0.33`, `yaw≈0°` | 안쪽 어깨/손목이 상대 어깨 근처, `side_by_side` |
| 손잡기 | `x≈±0.30`, `yaw≈0°` | 안쪽 손목끼리 `hold`, `side_by_side` |
| 등 맞대기 | `x≈±0.24`, 왼쪽 `yaw≈-96°`, 오른쪽 `yaw≈+96°` | 등/몸통 근접, `back_to_back` |
| 대치/전투 | `x≈±0.92`, `yaw≈±76°` | 접촉 없음 또는 공격/방어 `block` |

`interaction.contacts`는 의도된 접점을 표현한다. 현재 구현은 손·발의 월드 좌표를 계산해 거리를 강제하거나, 두 인물을 자동으로 맞추는 IK/충돌 엔진을 제공하지 않는다. 따라서 포옹·악수처럼 접촉이 중요한 요청은 포즈 적용 후 3D 미리보기에서 수동 보정해야 한다.

[`interactionMetrics`](../lib/pose/natural-language-map.ts)는 두 배치에서 거리·yaw 차이·상대 방향을 보는 정도를 계산해 모델의 후보를 피드백하거나 검증하는 용도다. 이는 관계 품질 점수이며 접촉 검증기가 아니다.

## 6. 검증된 예시를 우선 선택하는 방법

자연어 모델이 매번 관절을 처음부터 생성하면 리그 축을 잘못 해석할 위험이 크다. 첫 단계에서는 다음처럼 기존 프리셋을 검색·선택하고 필요한 관절만 미세 조정한다.

| 자연어 의도 | 단일 인물 프리셋 | 2인 프리셋 |
| --- | --- | --- |
| 서기·팔짱·경례·인사 | `base`, `arms_crossed`, `salute`, `bow_greet` | - |
| 앉기·무릎 꿇기·쪼그리기 | `sit`, `kneel`, `kneel_one`, `squat` | `kneel_look_up` |
| 걷기·달리기·점프 | `walk`, `run`, `sprint`, `jump` | `walk_together` |
| 펀치·가드·검 | `punch`, `guard`, `sword` | `attack_block`, `clash`, `standoff` |
| 대화·악수·포옹 | - | `talk`, `listen`, `handshake`, `hug` |
| 친밀·반응·춤 | - | `high_five`, `shoulder_arm`, `hold_hands`, `point_react`, `dance` |

프리셋의 라디안 수치는 [단일 프리셋](../components/pose-editor/presets.ts)과 [2인 프리셋](../components/pose-editor/duo-presets.ts)에 있다. 모델에 전달할 때는 다음 지시를 함께 사용한다.

> 기존 프리셋과 데이터 맵을 우선 사용해 `clicktoon.pose-intent/v1` JSON만 출력하라. 관절값은 도 단위의 기본 T 포즈 델타다. 2인 장면에는 각 인물의 `position`, `yawDegrees`, `role`, `interaction`을 반드시 포함하라. 접촉은 `contacts`에 의도로 기록하되, 접촉을 보장한다고 주장하지 말라. 인물 수는 1~3명, 모든 figure id는 고유해야 한다.

## 7. 임시 JSON 테스트 패널

`npm run dev` 개발 서버에서 `http://localhost:1059/?poseDebug=1`을 열면 오른쪽 맨 위에 **포즈 JSON 테스트** 패널이 나타난다. 일반 URL에서는 표시되지 않는다. `NODE_ENV=development`에서만 렌더링되며, 운영·미리보기·로컬 production 빌드에서는 `poseDebug` 쿼리가 있는 페이지 요청을 Proxy에서 404로 차단한다. 관리자로 로그인해도 배포 환경에서는 사용할 수 없다. 기존 일반 포즈 편집기는 그대로 사용할 수 있다.

1. **AI 컨텍스트 복사**를 눌러 외부 AI에 붙여 넣고 마지막 줄에 원하는 자세를 적는다. 클립보드를 사용할 수 없으면 **AI 컨텍스트 직접 복사**를 펼친다.
2. AI가 반환한 `clicktoon.pose-intent/v1` JSON을 입력창에 붙여 넣는다. JSON 코드 블록도 허용한다. 수치만 직접 수정해도 된다.
3. **포즈 적용**으로 장면을 확인한다. **2인 예시**는 입력창만 채우며 적용 버튼을 눌러야 장면이 바뀐다.
4. **현재 포즈 읽기**는 에디터에서 조정한 자세를 도 단위 JSON으로 가져온다. **적용 전으로 되돌리기**는 마지막 적용 직전의 인물·캐릭터 배정·자세를 한 번 복구한다. 페이지를 새로고침하면 되돌리기 기록은 사라진다.

[`debug-adapter.ts`](../lib/pose/debug-adapter.ts)는 JSON 형태를 검증한 후 기존 변환기를 호출한다. 입력 배열 순서로 기존 피규어 ID·캐릭터 배정을 유지하고 새 인물은 미배정으로 추가한다. 인물 수가 줄면 남는 인물은 장면에서 제거된다. AI의 `characterId`는 사용하지 않는다. 카메라·조명·출력 설정은 보존하며 범위를 넘는 관절·높이·크기의 보정은 패널에 표시한다.

적용은 기존 에디터의 자동 저장에도 반영된다. `interaction`은 테스트 결과 설명에만 사용하며 기존 `PoseState`에는 저장하지 않는다. 접촉을 자동 정렬하거나 AI를 직접 호출하지 않는다. 제거할 때는 `app/(app)/page.tsx`의 동적 import와 조건부 패널 연결, [`pose-debug-panel.tsx`](../components/pose-editor/pose-debug-panel.tsx), `debug-adapter.ts`를 제거하면 된다.

## 8. 향후 구현 순서

1. LLM 호출 전 자연어를 이 스키마로 제한하는 JSON schema/structured output을 도입한다.
2. `PoseIntentDraft`를 서버 또는 안전한 클라이언트 경계에서 Zod로 검증하고, 알려지지 않은 관절·범위 밖 값·중복 인물 ID를 거절한다. 현재 변환기는 안전 범위로 자르지만 JSON 형태 검증은 호출자가 해야 한다.
3. 후보를 바로 저장하지 말고 3D 미리보기·되돌리기·수정 UI를 거친다.
4. 월드 관절 좌표를 추출하고 손-손/손-어깨/발-바닥 접점의 거리 검사, 필요하면 IK를 추가한다.
5. 자연어 요청, 선택 프리셋, 최종 보정값, 실패 사례를 동의·개인정보 정책에 맞게 익명화해 평가 데이터셋으로 축적한다.

이 데이터 맵은 현재 Bony GLB 리그에만 유효하다. GLB 파일, 제어 관절, re-parenting 또는 축 보정을 바꾸면 이 문서·`POSE_LANGUAGE_DATA_MAP`·프리셋을 같은 변경에서 재검증해야 한다.
